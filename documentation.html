Les fonctions de
Claude Code

Claude Code est un agent IA pour le développement logiciel. Il dispose d'un ensemble d'outils (fonctions) qui lui permettent de lire, modifier et écrire du code, exécuter des commandes, rechercher sur le web, orchestrer d'autres agents et bien plus encore. Ce document décrit chaque fonction avec sa signature, ses paramètres et des exemples concrets.

Gestion des fichiers
3 fonctions · Read · Edit · Write
Read Core

Lit le contenu d'un fichier depuis le système de fichiers local. Supporte les fichiers texte, les images (PNG, JPG…), les PDF et les notebooks Jupyter. Retourne le contenu avec des numéros de ligne au format cat -n.

function Read( file_path: string, offset?: number, limit?: number, pages?: string // PDF seulement, ex: "1-5" ): string
file_path string Chemin absolu du fichier à lire Requis
offset number Numéro de ligne à partir duquel commencer la lecture Optionnel
limit number Nombre maximum de lignes à retourner (défaut : 2000) Optionnel
Retourne string — contenu du fichier avec numéros de ligne
Exemple — Lire un fichier complet
// Lire un fichier de configuration
Read({
  file_path: "/home/user/project/package.json"
})

// Résultat :
// 1  {
// 2    "name": "mon-projet",
// 3    "version": "1.0.0",
// ...
Exemple — Lire une plage de lignes
// Lire seulement les lignes 50 à 100 d'un grand fichier
Read({
  file_path: "/home/user/project/src/app.js",
  offset: 50,
  limit: 50
})
Edit Core

Effectue un remplacement de texte précis dans un fichier existant. Trouve la chaîne old_string et la remplace par new_string. La chaîne recherchée doit être unique dans le fichier, sinon il faut fournir plus de contexte. Toujours préférer Edit à Write pour modifier un fichier existant.

function Edit( file_path: string, old_string: string, // texte exact à remplacer new_string: string, // texte de remplacement replace_all?: boolean // remplacer toutes les occurrences ): void
file_path string Chemin absolu du fichier à modifier Requis
old_string string Texte exact à trouver (doit être unique dans le fichier) Requis
new_string string Texte de remplacement (doit être différent de old_string) Requis
replace_all boolean Si true, remplace toutes les occurrences du texte Optionnel
Exemple — Renommer une fonction
// Renommer une variable dans un fichier JavaScript
Edit({
  file_path:  "/home/user/src/utils.js",
  old_string: "function getUserData(id) {",
  new_string: "async function fetchUser(userId) {"
})
Exemple — Remplacer toutes les occurrences
// Renommer une variable partout dans le fichier
Edit({
  file_path:   "/home/user/src/config.js",
  old_string:  "API_URL",
  new_string:  "BASE_URL",
  replace_all: true
})
Write Core

Écrit du contenu dans un fichier. Écrase le fichier existant s'il y en a un. Utiliser uniquement pour créer de nouveaux fichiers ou pour des réécritures complètes. Pour les modifications partielles, préférer Edit.

function Write( file_path: string, content: string ): void
file_path string Chemin absolu du fichier à créer ou écraser Requis
content string Contenu complet à écrire dans le fichier Requis
Exemple — Créer un nouveau composant React
Write({
  file_path: "/home/user/src/Button.jsx",
  content:   `export function Button({ label, onClick }) {
  return (
    <button onClick={onClick} className="btn">
      {label}
    </button>
  );
}`
})

Recherche dans le code
2 fonctions · Grep · Glob
Grep Core

Recherche du texte ou des patterns regex dans les fichiers en utilisant ripgrep. Beaucoup plus rapide qu'un Bash grep. Supporte les regex complètes, le filtrage par type de fichier, le contexte de lignes, et plusieurs modes de sortie.

function Grep( pattern: string, // regex ripgrep path?: string, glob?: string, // ex: "*.ts", "**/*.jsx" type?: string, // ex: "js", "py", "rust" output_mode?: "files_with_matches" | "content" | "count", context?: number, "-i"?: boolean // insensible à la casse )
Exemple — Trouver tous les appels à une fonction
// Trouver où "fetchUser" est appelé dans le projet
Grep({
  pattern:     "fetchUser\\(",
  output_mode: "content",
  context:     2
})

// Résultat :
// src/api.js:14:  const user = await fetchUser(req.params.id);
// src/api.js:15:  if (!user) return res.status(404).send("Not found");
Exemple — Chercher uniquement dans les fichiers TypeScript
Grep({
  pattern: "interface\\s+\\w+",
  type:    "ts",
  output_mode: "files_with_matches"
})
Glob Core

Trouve des fichiers par pattern de noms (globbing). Retourne les chemins triés par date de modification (plus récent en premier). Idéal pour localiser des fichiers sans connaître leur emplacement exact.

function Glob( pattern: string, // ex: "**/*.tsx", "src/**/*.test.js" path?: string // répertoire de base ): string[]
Exemple — Trouver tous les fichiers de test
Glob({
  pattern: "**/*.test.{js,ts,jsx,tsx}",
  path:    "/home/user/project"
})

// Résultat :
// [
//   "src/components/Button.test.tsx",
//   "src/utils/format.test.js",
//   "src/api/users.test.ts"
// ]

Exécution de commandes
1 fonction · Bash
Bonne pratique : Préférer les outils dédiés (Read, Grep, Glob) quand c'est possible. Bash est réservé aux opérations shell qui n'ont pas d'outil équivalent : git, npm, tests, compilation, etc.
Bash Util

Exécute une commande shell et retourne sa sortie. Le répertoire courant persiste entre les appels, mais l'état du shell non. Supporte les commandes longues via run_in_background et un timeout configurable.

function Bash( command: string, timeout?: number, // ms, max 600 000 (10 min) run_in_background?: boolean // ne pas attendre la fin ): string
Exemple — Opérations Git courantes
// Voir l'état du dépôt
Bash({ command: "git status" })

// Créer et pousser une branche
Bash({ command: "git checkout -b feature/auth && git push -u origin feature/auth" })

// Faire un commit
Bash({ command: `git add src/auth.js && git commit -m "feat: add JWT authentication"` })
Exemple — Lancer les tests en arrière-plan
// Démarrer le serveur de dev sans bloquer
Bash({
  command:            "npm run dev",
  run_in_background: true
})

// Installer des dépendances (max 5 minutes)
Bash({
  command:  "npm install",
  timeout:  300000
})

WebSearch Util

Effectue une recherche sur le web et retourne une liste de résultats (titres, URLs, extraits). Utile pour trouver de la documentation, des exemples de code récents, ou vérifier des informations.

function WebSearch( query: string ): SearchResult[]
Exemple — Chercher la doc d'une API
WebSearch({
  query: "React Server Components streaming Next.js 15"
})

// Retourne une liste de résultats avec titre, URL et extrait
WebFetch Util

Récupère et lit le contenu d'une URL. Convertit la page web en texte lisible. Idéal pour lire une documentation en ligne, un article, ou le contenu d'un Artifact existant.

function WebFetch( url: string, prompt?: string // question spécifique sur le contenu ): string
Exemple — Lire la documentation officielle
WebFetch({
  url:    "https://react.dev/reference/react/useState",
  prompt: "Quelles sont les règles d'utilisation de useState ?"
})

IA & Orchestration d'agents
2 fonctions · Agent · Workflow
Agent Power

Lance un sous-agent IA capable d'exécuter des tâches complexes en autonomie. Les agents tournent en arrière-plan par défaut. Idéal pour les recherches larges dans le codebase, les analyses indépendantes, ou les tâches qui consommeraient trop de contexte.

function Agent( description: string, // 3-5 mots résumant la tâche prompt: string, // instructions détaillées subagent_type?: string, // "Explore", "general-purpose", etc. run_in_background?: boolean, isolation?: "worktree" | "remote" ): Promise<string>
description string Titre court de la tâche (affiché dans l'interface) Requis
prompt string Instructions complètes — doit être auto-suffisant (l'agent n'a pas le contexte de la conversation) Requis
subagent_type string "Explore" pour la recherche, "general-purpose" pour tout, "code-reviewer" pour les revues Optionnel
Exemple — Exploration du codebase
Agent({
  description:    "Audit des appels API",
  subagent_type: "Explore",
  prompt: `Explore le dossier /home/user/project/src et liste
tous les appels fetch() ou axios. Pour chaque appel,
note l'URL, la méthode HTTP et le fichier source.
Réponds sous forme de tableau JSON.`
})
Exemple — Deux agents en parallèle
// Lancer deux analyses indépendantes en même temps
// En envoyant les deux dans le même message
Agent({ description: "Audit sécurité frontend", prompt: "..." })
Agent({ description: "Audit sécurité backend",  prompt: "..." })
// Les deux tournent en parallèle → résultat 2x plus rapide
Workflow Power

Orchestre plusieurs agents de façon déterministe via un script JavaScript. Supporte pipeline() (parallèle en cascade), parallel() (barrière), et phase() (groupes de progression). Idéal pour les migrations de code, les audits exhaustifs, ou les tâches à grande échelle.

function Workflow( script?: string, // script JS inline scriptPath?: string, // chemin vers le script args?: any, // paramètres passés au script name?: string // workflow prédéfini ): Promise<any>
Exemple — Revue de code multi-dimensions
Workflow({
  script: `
export const meta = {
  name: 'code-review',
  description: 'Revue de code sur 3 dimensions',
  phases: [{ title: 'Analyse' }, { title: 'Vérification' }],
}

const DIMENSIONS = [
  { key: 'bugs',     prompt: 'Trouve les bugs potentiels dans src/' },
  { key: 'perf',     prompt: 'Analyse les problèmes de performance' },
  { key: 'security', prompt: 'Détecte les vulnérabilités de sécurité' },
]

// pipeline = chaque dimension vérifie dès qu'elle a ses résultats
const results = await pipeline(
  DIMENSIONS,
  d => agent(d.prompt, { label: d.key, phase: 'Analyse' }),
  r => agent('Vérifie et confirme: ' + r, { phase: 'Vérification' })
)

return results`
})

Intégration GitHub
Via MCP · Pull Requests · Issues · CI
GitHub MCP API

Outils d'intégration GitHub via le protocole MCP (Model Context Protocol). Permettent de gérer les pull requests, issues, commentaires, et le statut CI directement depuis Claude Code, sans avoir besoin du CLI gh.

// Fonctions disponibles (préfixe mcp__github__) mcp__github__create_pull_request(title, body, base, head) mcp__github__get_pull_request(pull_number) mcp__github__list_pull_requests(state) mcp__github__create_issue(title, body, labels) mcp__github__add_issue_comment(issue_number, body) mcp__github__get_file_contents(path, ref) mcp__github__search_code(query)
Exemple — Créer une Pull Request
mcp__github__create_pull_request({
  owner:  "moncompte",
  repo:   "mon-projet",
  title:  "feat: ajout de l'authentification JWT",
  body:   "## Résumé\n- Ajout du middleware JWT\n- Tests unitaires",
  head:   "feature/jwt-auth",
  base:   "main"
})

Interface & Suivi
3 fonctions · Artifact · TodoWrite · Skill
Artifact Core

Publie une page HTML ou Markdown comme artifact hébergé sur claude.ai. La page est privée par défaut mais peut être partagée. Chaque publication à la même URL met à jour la page existante. La page est entièrement autonome (pas de CDN externe).

function Artifact( file_path: string, // fichier .html ou .md favicon: string, // emoji pour l'onglet navigateur description?: string, // sous-titre de la carte label?: string, // nom de version url?: string // URL existante à mettre à jour ): string // retourne l'URL publique
Exemple — Publier ce document
// 1. Écrire le HTML
Write({
  file_path: "/tmp/doc.html",
  content:   "<h1>Ma documentation</h1>"
})

// 2. Publier comme Artifact
Artifact({
  file_path:   "/tmp/doc.html",
  favicon:     "📚",
  description: "Documentation du projet",
  label:       "v1.0"
})
TodoWrite Util

Gère une liste de tâches pour suivre l'avancement d'une mission complexe. Affiche les tâches dans l'interface et permet de les marquer comme completed, in_progress ou pending.

type Task = { id: string, content: string, status: "pending" | "in_progress" | "completed", priority: "low" | "medium" | "high" } function TodoWrite(todos: Task[]): void
Exemple — Suivi d'une refactorisation
TodoWrite([
  { id: "1", content: "Analyser le code existant",     status: "completed",   priority: "high"   },
  { id: "2", content: "Écrire les nouveaux composants",  status: "in_progress", priority: "high"   },
  { id: "3", content: "Mettre à jour les tests",          status: "pending",     priority: "medium" },
  { id: "4", content: "Créer la pull request",            status: "pending",     priority: "low"    },
])
Skill Core

Invoque une compétence spécialisée (slash command). Les skills sont des programmes préenregistrés qui définissent comment aborder une catégorie de tâches : revues de code, recherches approfondies, visualisations, initialisation de projets, etc.

function Skill( skill: string, // nom exact du skill args?: string // arguments optionnels ): void
Exemple — Skills courants
// Revue de code sur le diff en cours
Skill({ skill: "code-review",   args: "--fix" })

// Recherche approfondie multi-sources
Skill({ skill: "deep-research", args: "Meilleures pratiques WebSockets 2025" })

// Créer un graphique / visualisation
Skill({ skill: "dataviz" })

// Vérifier qu'un changement fonctionne en conditions réelles
Skill({ skill: "verify" })

// Revue de sécurité des changements en cours
Skill({ skill: "security-review" })
Note : Un skill doit apparaître dans la liste des skills disponibles avant de pouvoir être invoqué. Pour utiliser un skill, l'utilisateur peut aussi taper /nom-du-skill directement dans le chat.
